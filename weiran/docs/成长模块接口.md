# 成长模块接口（第 ④ 部分，2026-10-02）

三个页面：`pages/plan/plan`、`pages/check-in/check-in`、`pages/weekly-report/weekly-report`。业务入口为 `utils/growth-store.js`，纯统计为 `utils/growth-metrics.js`，新增演示明细为 `utils/growth-mock.js`。

## 日期与边界

复用当前学生的 `store.getAcademicStatus().asOf` 作为统一模拟日期，初始 2026-06-29。`growth.advanceDay()` 只推进日期，不制造成绩或记录，不直接修改预警值。首次预警重播可能回退日期；未来记录和未来创建的计划不参与当前视图。真正操作时间只作为审计字段。

学习记录、任务完成、周报不写入既有 learning/warnings，不修改任何风险评分或分级算法。界面注明模拟日期与来源。压力自评范围 0–20，固定 `stress-self-v1-20`，与旧问卷为独立数据序列。

## growth-store 公共接口

所有读写只作用于当前会话，不从页面接收 studentId。

- `getContext()` → `{ student: {id,name,nickname}, today, earliestDate, initialPlanEndDate, latestPlanDate, settings }`。初始计划截止最多为 today+6；延期最多为 today+30。
- `getPlanSuggestion()` → `{ title, reason, sourceWarningId: string|null, tasks: [{title,dueDate}] }`，默认 7 天内三个可编辑任务。
- `createPlan({title, sourceWarningId, tasks:[{title,dueDate}]})` → `{plan,reused}`。同源预警幂等，个人计划同一周最多一个。需 1–8 项任务。
- `getPlans()` → 最近创建优先的计划数组，每项包含 `stats` 及任务的 `overdueDays/statusLabel`。未来创建计划不展示。
- `updateTask(planId, taskId, action, options)`：action 为 `complete` / `postpone` / `cancel`，延期 options 为 `{dueDate,reason}`。延期只允许未完成任务且日期晚于原期限，必须记录原因。
- `getDailyRecord(date)` → 当前日期的记录或 null。受显示设置限制，隐藏字段不返回；有 `revision/origin/updatedAt`。
- `saveDailyRecord({date,learningMinutes,exerciseMinutes,sleepHours,pressureScore})` → 保存后的记录；空字符串按缺失值处理。遗漏字段、已隐藏字段保留原值。有效范围学习/运动 0–1440 整数，睡眠 0–24 小时，压力 0–20 整数；无任何值不能保存；睡眠归属醒来当天。
- `deleteDailyRecord(date)`：仅删除当前用户该日数据并留审计，UI 必须明确确认。
- `getRecordHistory()` → 最近 14 日可见的当前记录，日期降序；隐藏字段不返回。
- `getReport()` → 下述周报结构，自动应用显示开关。
- `getDashboardSummary()` → `{today,planCount,activeTasks,completedTasks,completionPercent,recordedToday,learningMinutes,reportStatusLabel,reportStatusKey}`，不输出隐藏健康/心理数据。
- `advanceDay()` → 新日期。

计划基本结构：`{id,studentId,title,sourceWarningId,createdDate,startDate,endDate,createdAt,tasks[]}`。任务：`{id,title,originalDueDate,dueDate,status:'pending'|'completed'|'canceled',completedDate,canceledDate,createdDate,changeLog[]}`。

每日记录：`{date,learningMinutes:number|null,exerciseMinutes:number|null,sleepHours:number|null,pressureScore:number|null,scaleVersion,revision,origin:'mock'|'self',sources:{},updatedAt}`。同日更新而非追加；旧版本写入独立审计历史。

## growth-metrics 纯函数

- `calculatePlanStats(plan,asOf)` → `{total,active,completed,canceled,overdue,dueCount,onTimeCount,rescheduled,completionPercent:number|null,onTimePercent:number|null}`。完成率排除取消项；**按时率始终以 originalDueDate 判断**，避免通过延期改善成绩；逾期按当前 dueDate 判断。无分母返回 null，百分比保留一位小数。
- `buildReport({asOf,joinedOn,records,learning,plans,settings})` →

```text
{
  period: {from,to,label,previousFrom,previousTo,previousLabel},
  status: {key:'improving'|'stable'|'declining'|'insufficient',label,description},
  academic: [MetricCard],
  wellbeing: [MetricCard],
  coverage: {days,expected,percent,label},
  studyBars: [{date,label,value:number|null,height:number,isMissing:boolean}],
  advice: [string],
  methods: [{title,formula}],
  sourceLabel: string
}
MetricCard = {key,label,valueText,detail,previousText,changeText,
              tone:'good'|'neutral'|'warn'|'muted',source,formula}
```

窗口为 `[asOf-6,asOf]` 与 `[asOf-13,asOf-7]`，页面称“近 7 天”。总评只来自可比的教务出勤/作业明细，不把自报时长越高当作越好。缺失不计作零；不同量尺不比较。自报记录两窗至少各 4 天才比较均值。健康模块控制运动/睡眠，心理模块控制压力；卡片、建议、方法解释均需要同步过滤。

`learning`：`{attendance:[{id,date,attended:boolean,excused:boolean}], assignments:[{id,dueAt,submittedAt:string|null}]}`。任务提交时间为带 `+08:00` 的 ISO 时间。按窗口内到期作业统计，未到截止时间的作业不应作为到期分母（演示统计截止为 asOf 当日 23:59:59+08:00）。请假课次排除。周报不由旧累计比例反推明细。

## growth-mock

导出 `JOINED_ON='2026-06-01'`、`getStudentFixtures(studentId)`。返回 `{records,learning,scenarioLabel}`，按当前已有六名学生提供独立、明确标记的两周演示明细。黄/池：持平；魏：下降；赖/汪：改善；郭：不足。日均睡眠、运动、自评为示例而非建议阈值。
