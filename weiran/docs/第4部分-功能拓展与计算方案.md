# 第 ④ 部分：学生成长支持与效果评估

本文件是后续开发建议，不表示这些拓展功能已经实现。本轮代码修改主要修复现有问题。

建议把“拓展更多功能与更多计算”收敛成一个可以独立交付的模块：让学生知道为什么收到提醒、可以采取什么行动、行动后有哪些变化。首批完成“改善计划 + 自主记录 + 成长周报”，再增加推荐反馈和数据质量说明。

## 1. 与其他成员的分工边界

| 分工 | 负责内容 | 与第 ④ 部分的接口 |
| --- | --- | --- |
| ① 预警值计算 | 数据归一化、权重、阈值、预警等级、算法校验 | 输出带版本的分数、原因、贡献项、时间窗、可信程度 |
| ② 虚拟 IP | 形象、表达方式、对话入口或能力 | 消费第 ④ 部分生成的计划和周报；完成动作仍写回统一业务层 |
| ③ 界面优化 | 视觉系统、组件、页面布局、交互呈现 | 第 ④ 部分给出数据、页面状态和交互规则，双方约定组件接口 |
| ④ 功能拓展 | 自主记录、计划执行、趋势复盘、推荐反馈、数据质量 | 将预警结果转成可操作的学生服务，记录过程与结果 |
| ⑤ 网页端 | 辅导员列表、详情、预警处置、反馈处理 | 读取升级事件、求助记录和经授权可见的计划摘要，回传处理状态 |

评分阈值只由 ① 维护。④ 不再维护另一套预警算法，也不根据打卡次数直接修改预警分。现有 `academic-rules.js` 只判断观察期内是否升级提醒，不负责生成分数。

## 2. 第一优先级：一周改善计划

当前问题：学生点击“自助处理”只会留下记录，还没有后续行动。

建议流程：学业预警 → 选择自助 → 展示可编辑的 7 天计划 → 学生确认 → 完成/延期/取消任务 → 查看进展与复盘。模板由规则生成，MVP 无需调用大模型。

示例：汪同学作业提交为 8/12，先生成“联系老师确认可补交作业”“完成两次复习练习”“安排一次答疑”三个任务。不能假定所有缺交作业都允许补交；已提交的自报任务与教务平台回传的作业记录应分开保存。

计算与边界：

- 任务完成率 = 已完成任务数 / 当前有效任务数。取消任务不参与分母；没有任务显示“暂无计划”。
- 按时完成率 = 截至统计日已到期任务中按时完成的数量 / 截至统计日已到期的有效任务数。分母为零时显示“暂无到期任务”。
- 逾期天数 = 统计日期与到期日期的天数差，仅对未完成且已到期任务计算。
- 每条任务记录 `sourceWarningId`，防止反复点击“自助”生成重复计划。延期保存原期限与新期限，避免修改期限后丢失过程记录。

数据：`planId, studentId, sourceWarningId, createdAt, startDate, endDate, tasks[]`；任务包含 `taskId, title, dueDate, status, completedAt, selfReported, changeLog[]`。

验收：汪同学创建计划、完成其中一项，完成率能变化；退出再进入仍保留；切换黄同学看不到该计划；重复点击不会生成多个同源计划。

## 3. 第一优先级：自主记录与轻量问卷

当前项目的运动、压力和兴趣来自写死的 Mock。新增可填写入口，才能演示“输入数据 → 更新画像 → 重新计算 → 反馈给学生”。

建议首批输入：当天自主学习分钟数、运动分钟数、睡眠时长、简单的主观压力自评，以及研究兴趣。学生可以跳过部分问题、修改当天记录；标明“自主填写”，与教务、门禁等来源区分。

计算与边界：

- 最近 7 天运动总时长 = 该窗口内有效运动记录之和。
- 记录覆盖率 = 有有效记录的日期数 / 应记录日期数；首次使用不足 7 天时，分母取实际加入后的日期数，最多 7。
- 平均睡眠时长 = 有效睡眠时长之和 / 有记录天数；同时展示“统计 4/7 天”，缺失不能按零小时处理。
- 周自评变化 = 本周有效记录均值 − 上周有效记录均值；两周至少各有约定数量的记录才能展示差值。最低数量需在产品中明确，先建议各 4 天作为演示规则。

相同学生、日期和记录类型只有一条当前记录，修改留版本。自评只是自我观察，不据此生成临床诊断。未经填写或授权的数据标记为缺失，不补造数值。

数据：`studentId, localDate, learningMinutes, exerciseMinutes, sleepHours, pressureSelfRating, source, updatedAt, version`。必须说明睡眠记录归属“醒来当天”，避免跨午夜计数不一致。

与 ① 对接：只提供原始值、来源和统计窗口，预警值仍由统一评分模块更新。问卷量尺需要版本号，换量尺后的分数不能直接与旧量尺比较。

## 4. 第一优先级：成长周报与变化解释

建议每周显示 3–5 个与当前问题相关的指标，优先展示学习数据，同时标出数据来源和时间窗。

推荐计算：

| 指标 | 定义 | 必须说明的边界 |
| --- | --- | --- |
| 出勤率变化 | 本周出勤率 − 上周出勤率 | 单位为百分点；需要每周应到/实到课次，当前单个累计比例无法推导 |
| 作业按时提交率 | 窗口内到期且按时提交的作业数 / 窗口内到期的有效作业数 | 当前只有提交总次数，需要补 `dueAt/submittedAt` |
| 学业关注值降幅 | (基线值 − 当前值) / 基线值 | 基线为零时不计算；算法版本和量尺必须相同 |
| 计划完成率变化 | 本周与上周可比计划完成率之差 | 计划难度可能不同，不直接归因于某项干预 |
| 数据覆盖情况 | 有效记录数与应有记录数 | 用于提示结论完整性，不称为“预测准确率” |

建议报告措辞：“计划执行期间，出勤率从 78% 变为 86%，提高 8 个百分点。”不要直接写“因为计划，出勤率提高了 8 个百分点”；前后变化只能描述关联。

MVP 使用固定模板生成可解释的周报即可。至少准备“改善 / 持平 / 恶化 / 数据不足”四种 Mock 状态，不必等真实一周过去。

## 5. 第二优先级：兴趣推荐与反馈

学生可编辑研究兴趣，对赛事和资源选择“感兴趣 / 收藏 / 不感兴趣”，让推荐从静态列表变成可调整的功能。

初版可用透明的标签匹配：兴趣匹配度 = 命中的学生兴趣标签数 / 学生已选兴趣标签数；无兴趣时展示通用资源，不强行输出匹配百分比。先排除已结束、年级不符或被明确屏蔽的资源，再排序。这个数值表示标签重合程度，不代表获奖概率或适合度的科学测量。

推荐来源优先使用研究兴趣、课程需求和学生反馈。MBTI 只作为学生自述信息展示，不作为学业风险或心理状态的评分依据。

新增数据：资源 `id, tags[], eligibleGrades[], deadline, sourceUrl, isMock`；反馈 `studentId, resourceId, action, createdAt`。当前静态通知不含完整资源信息，需要独立资源表。

验收：郭同学选择“数据科学”后能看到解释“与你选择的方向匹配”；点“不感兴趣”后减少同类推荐；模拟赛事必须明确标记，无真实链接时不显示可报名按钮。

## 6. 第二优先级：数据质量与解释卡片

每个结论都能回答“用哪些数据得出、数据什么时候更新、有没有缺项”。对已经存在的字段来源/用途页面进行扩展即可。

- 完整度：必需字段中有效字段的比例。范围合法不代表数据真实，不能称为“可信度概率”。
- 新鲜度：统计日距最近更新日的天数。按来源配置有效期，而非所有字段统一 7 天。
- 一致性：同一时间窗的寝室进出次数应一致；作业提交数不能大于应交数；缺失值与零值区分。
- 反馈联动：学生反馈数据错误后，结论标记“相关数据待核实”；反馈提交不直接覆盖教务原始数据。

需要先补齐时间窗、字段级更新时间和反馈关联字段。① 可根据这些状态决定暂停评分、降低结论强度或标注数据不足。

## 7. 建议暂缓的方向

暂缓人际关系评分、性格优劣排名、使用门禁直接推断心理问题、对个人给出未经验证的挂科概率。这些方向对数据质量与验证要求高，也会扩大你与第 ① 部分的重叠。

图书馆时长可以作为行为记录，但不能当作有效学习时长。寝室出入次数无法表示离开寝室多长时间；若确实需要计算久未外出，必须先有经授权且完整的出入时间记录，并处理离校、门禁遗漏等情况。

## 8. 接口与交付顺序

与 ① 约定的结果格式建议：

```json
{
  "studentId": "s005",
  "dimension": "learning",
  "score": 62,
  "level": "low",
  "calculatedAt": "2026-06-29T09:00:00+08:00",
  "algorithmVersion": "demo-v1",
  "period": { "from": "2026-06-01", "to": "2026-06-29" },
  "drivers": [{ "field": "homeworkSubmitted", "reason": "有 4 次作业尚未提交" }],
  "quality": { "status": "sufficient", "missingFields": [] }
}
```

交付顺序：

1. 与 ① 确认结果格式、字段单位和时间窗。
2. 完成计划创建、执行、持久保存，接到现有“自助处理”按钮。
3. 完成自主记录表单与必要校验，准备跨周 Mock 明细。
4. 完成周报计算和四种演示状态。
5. 补兴趣推荐反馈、数据质量卡片。

第一个可演示版本控制在三个新增页面：我的计划、今日记录、成长周报。② 的锅包肉入口可打开同一计划详情，⑤ 只接收用户求助及必要摘要，避免多人各自维护一份计划状态。

## 9. 可参考的原则

Jisc 的学习分析实践指南强调数据透明、结果有效性和对学生有帮助的干预。这里据此建议把“可解释的数据 + 学生可采取的行动 + 效果复盘”作为拓展重点；上述功能和公式是针对本项目的设计建议，不是该指南规定的评分标准。来源：[Code of practice for learning analytics](https://www.jisc.ac.uk/guides/code-of-practice-for-learning-analytics)。
