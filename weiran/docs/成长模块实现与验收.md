# 第 ④ 部分：成长支持模块

实现日期：2026-10-02。三个原生小程序页面已经接入首页、个人中心和预警自助流程；继续使用本地 Mock 和本地存储，无需安装依赖。

## 本轮策略

第 ④ 部分先补齐“提醒之后怎么办”：学生确认计划、记录行动、查看过程变化。重点是可执行、可解释、可复盘，避免不断堆叠未经验证的评分。

- ① 继续负责预警评分与分级。成长模块不改学业风险分，也不把打卡完成等同于风险消除。
- ② 可后续读取同一份计划和周报；本轮没有新增真实对话能力。
- ③ 可继续统一组件与视觉系统；新增页面沿用纸页色与现有样式。
- ⑤ 保留网页框架。本轮没有伪造跨端数据同步或发送辅导员消息。

## 已完成的学生体验

### 一周计划

在预警详情选择“自助处理”后，先记录处理选择，再打开可编辑建议。只有确认创建后才参与统计。无预警的学生也可以创建个人学习计划。

每份计划有 1–8 项任务，初始期限在模拟当天至第 7 天之间。任务可完成、延期、取消；延期必须晚于现期限、填写原因，新日期最多为模拟当天之后 30 天。日志保留原期限、新期限、原因、模拟操作日期和实际操作时间。

同一预警周期保留一份计划；个人计划按周一至周日去重。任务完成或取消后不能再次操作。取消项仍保留，排除出完成率和按时率分母。

### 每日记录

支持自主学习分钟数、运动分钟数、睡眠小时数、0–20 压力自评，各项可跳过。睡眠记录归属醒来当天。范围合法的 0 是有效记录，空白表示缺失；不能保存完全没有可见有效值的表单。

允许补记 2026-06-01 至当前模拟日，禁止填未来日期。同日修改更新唯一当前记录并保留上一版本；删除需确认，审计保留删除前内容；删除后重新填写继续递增版本。重复保存相同值不制造修订。

初始示例有字段级来源。只修改学习时长时，运动、睡眠、自评的示例来源不会被一并改成“本人填写”。查看近 14 天历史可返回对应日期修改；表单有未保存内容时，切换日期或推进模拟日期会提醒。

显示设置同样控制新页：关闭健康显示隐藏运动与睡眠，关闭心理显示隐藏压力。在这些字段隐藏时修改学习记录，会保留原先隐藏的值。删除当天整条记录会连同隐藏字段删除，确认框会说明这一点。

### 成长周报

页面名称为成长周报，实际按滚动的两个 7 天窗口统计，不冒充自然周。初始本期为 2026-06-23 至 06-29，对比期为 06-16 至 06-22。

学习指标排在最前：出勤率、作业按时提交率、日均自主学习、计划任务按时率。生活指标遵循显示设置；隐藏时卡片、计算说明和来源汇总同步过滤。

报告提供每天的学习时长柱状图、记录覆盖率、样本数量、来源、计算方式和基于规则的下一步建议。零分钟与未填写在图表上有不同标记。学习时长变长本身不代表效果改善，自评不用于诊断。

## 计算口径

| 计算 | 分母与边界 |
| --- | --- |
| 任务完成率 | 已完成 ÷ 未取消任务；没有有效任务显示空值 |
| 任务按时率 | 原定已到期且按原期限完成 ÷ 原定已到期的未取消任务；提前完成但原期限尚未来临的任务暂不计入；延期不能改写原期限 |
| 逾期天数 | 未完成任务的统计日减当前期限；到期当天为 0，次日为 1 |
| 出勤率 | 有效出勤 ÷ 应到课次；批准请假排除，未知状态不强算缺勤；两个窗口各至少 3 节才比较 |
| 作业按时提交率 | 按时提交 ÷ 窗口内到期作业；截止为模拟日北京时间 23:59:59；迟交计入已提交但不计按时，未来提交不提前生效 |
| 自主记录均值 | 有效值之和 ÷ 有效天数；缺失不当作 0；两个窗口各至少 4 天才比较；压力仅使用同一量尺版本 |
| 记录覆盖率 | 至少有一个可见有效字段的天数 ÷ 应记录天数；分母不超过加入至今的天数，最多 7 天 |

“学习过程改善 / 持平 / 下降”是演示性的过程描述：两个窗口的出勤率、作业按时率都满足最低样本量后，计算两项变化的等权平均；达到 +5 个百分点判为改善，达到 −5 判为下降，其余持平。样本不够显示“样本不足”。分类使用未舍入的比率，展示值保留一位小数。这不是预警评分，也不能证明变化由计划造成。

## 六名学生如何演示

| 学生 | 初始过程趋势 | 适合展示 |
| --- | --- | --- |
| 黄同学 | 持平 | 无预警也可建立个人计划 |
| 池同学 | 持平 | 运动记录、健康显示开关与通知开关分别控制 |
| 魏同学 | 下降 | 过程下降提示、压力自评与心理显示开关 |
| 赖同学 | 改善 | 改善场景、过程指标与原有资源推荐并存 |
| 汪同学 | 改善 | 预警自助 → 确认计划 → 完成/延期/取消 → 复盘；过程改善不自动消除学业预警 |
| 郭同学 | 样本不足 | 不足的数据不生成确定趋势 |

建议先登录汪同学：确认一份计划，完成第一项，3 项未取消任务的完成率应为 33.3%；再延期另一项并填写原因。进入每日记录修改学习分钟数，周报立即刷新该记录的均值。切换黄同学，不能看到汪同学的计划。关闭健康/心理显示后重进新页，对应字段消失；重新打开可看到原记录。

初始示例并不持续生成。推进模拟日后，窗口滚动且可能出现样本不足；这是数据覆盖的真实演示。预警页“重播首次提醒”回退同一时钟，未来记录和计划不显示，未来操作按日志回放过滤；已存在未来同源计划时拒绝重复创建。

## 文件与对接

- `miniprogram/utils/growth-store.js`：当前会话范围内的计划和记录业务，存储键 `wr_growth_v1` 按学生隔离；`recordAudit` 保存修订和删除历史。
- `miniprogram/utils/growth-metrics.js`：不依赖微信 API 的纯统计，输入不会被修改。
- `miniprogram/utils/growth-mock.js`：六人的两周教务过程与自主示例。它独立于旧累计画像，不从累计比例反推，不回写 `mock.js`。
- `pages/plan`、`pages/check-in`、`pages/weekly-report`：三个页面；`styles/growth.wxss` 为共用样式。
- `store.advanceDemoDate`：复用原有预警演示时钟，单独推进日期不制造新样本；已有观察规则仍按日期判断。
- 完整数据形状与函数约定见《成长模块接口.md》。后续②⑤应复用这一业务接口，经授权读取必要内容，避免独立维护多份计划。

## 验证

在仓库根目录执行 `node --test weiran/tests/*.test.cjs`，本轮 **86 项全部通过**：原 MVP 23 项、纯统计 22 项、成长业务 23 项、页面交互 18 项。测试使用模拟微信 API，不修改开发者工具缓存。

真实微信 WXML/WXSS 独立编译器检查 17 个页面；脚本已支持共同导入的样式文件。使用 WXML 编译产物进行了 320/375 像素宽度的浏览器近似排版检查，未发现横向溢出。浏览器近似检查不等同于微信模拟器或真机联调；微信授权、系统键盘、日期选择器及返回手势仍需真机验收。
